产品 01 · CORE CASE

室内设计 Agent（暗壳AI）

SPATIAL DESIGN AGENT · SKILLS · MEMORY · EVALUATION

项目背景

面向室内设计师、家居品牌与企业设计团队，建设覆盖“设计需求理解—方案规划—空间效果生成—商品匹配—交易履约”的智能空间设计系统。针对传统设计流程中需求沟通成本高、方案生产周期长、专业工具门槛高，以及设计方案与真实商品供应链割裂等问题，主导构建具备意图理解、任务拆解、自主推理和技能调用能力的空间设计 Agent，并连接 3000+ 家居品牌供应链，让设计创意能够进一步转化为可选购、可交付的商业方案。

核心产品能力

  • 设计需求理解：通过多轮对话识别空间类型、户型条件、设计风格、预算、居住人群与功能诉求，将“现代、温馨、有高级感”等模糊表达转化为空间布局、材质、色彩、家具和灯光等结构化设计约束。
  • 空间设计 Agent：规划需求澄清、知识检索、方案推理、技能调用与结果校验链路，由 Agent 根据任务自主选择空间生成、局部改造、商品替换和方案优化等 Skills，形成从用户意图到设计结果的完整执行闭环。
  • 三级知识库与记忆：从 0 到 1 设计行业、企业、项目三级知识体系。行业库沉淀设计规范、风格与空间方法；企业库管理品牌商品和业务规则；项目库记录客户需求、历史方案与修改反馈，增强知识检索、上下文记忆及企业级定制能力。
  • 设计交易与供应链：将生成方案中的家具、建材与真实 SKU 进行匹配，规划商品推荐、清单管理、订单管理和 ERP 履约链路，打通“AI 设计生成—实景导购—下单采购—交付履约”的设计交易闭环。

Agent 评测机制

  • 意图理解评测：评估空间信息提取、模糊需求澄清、约束识别与上下文记忆的准确性，验证 Agent 是否真正理解用户想解决的设计问题。
  • 任务规划评测：围绕任务拆解、Skills 选择、技能路由、参数传递和异常降级建立 Benchmark 测试集，检查执行链路是否合理、稳定且可恢复。
  • 结果质量评测：从空间结构合理性、风格一致性、视觉质量、商品可匹配性和方案可落地性评估输出，并通过人工评审与模型评测结合降低单一指标偏差。
  • 迭代闭环：对失败任务进行 Badcase 分类，定位知识缺失、Prompt 策略、模型能力或技能调用问题，将结果回流至知识库、测试集和产品策略，形成“评测—反馈—优化—回归测试”的持续迭代机制。

产品 04

AI 实景导购小程序

AI COMMERCE · SKU MATCHING · PROCUREMENT

项目背景

基于暗壳空间设计 Agent，规划面向家居品牌与线下卖场的 B 端 AI 导购小程序，服务三棵树、东鹏瓷砖、红星美凯龙卖场等商家。产品帮助导购将消费者的真实空间快速转化为商品应用效果，通过一键替换墙面材质、瓷砖或家具，让客户在购买前直观看到搭配结果，并将效果方案直接关联至商家真实商品 SKU，缩短从选品、体验到采购的决策链路。

核心产品能力

  • B 端商品接入：将品牌涂料、瓷砖、家具等商品素材与 SKU 建立关联，形成可被 Agent 检索、推荐和调用的商家商品库，支持不同品牌与卖场快速配置专属导购内容。
  • 一键换材与换家具：导购上传客户空间照片后，可选择墙面、地面或家具区域，一键替换为三棵树涂料、东鹏瓷砖或卖场家具商品，快速生成贴近真实空间的应用效果。
  • AI 场景化导购：根据客户空间条件、风格偏好和选购需求推荐适配商品，通过效果对比与组合搭配辅助导购讲解，降低客户对材质、尺寸和整体效果的理解成本。
  • 一键采购闭环：将客户确认的材质与家具自动映射至商品 SKU，生成商品清单并连接采购入口，打通“空间上传—效果替换—方案确认—SKU 清单—一键采购”的完整链路。
产品 02 · 0→1 CASE

观境 GUANJING · 城市文化体验 Agent

CULTURAL TRAVEL AGENT · RAG · MEMORY · PLANNING

项目背景

面向希望深入理解中国城市的入境游客，建设以“城市空间—城市展览—文化体验”为核心的智能旅行产品。产品聚焦深圳与北京两座重点目的地，通过城市文化知识库与 Agent，将建筑、街区、艺术机构、博物馆、展览和在地文化活动组织成可探索、可理解、可执行的主题体验；天气、美食、交通等通用旅行信息作为辅助条件，为文化行程提供必要的决策支持。

核心产品能力

  • 用户画像与旅行记忆：建立“基础行程—文化兴趣—行为偏好—长期记忆”四层画像体系。
    • 基础行程：记录语言、出行天数、同行关系、预算和行动能力。
    • 文化兴趣：识别用户对建筑、城市更新、当代艺术、饮食、科技与地方生活等主题的偏好。
    • 行为偏好：持续分析收藏、跳过、停留和路线修改等行为路径。
    • 长期记忆：沉淀用户对空间类型、讲解深度和旅行节奏的稳定偏好，为后续推荐与行程调整提供上下文。
  • 空间知识、文化体验与 RAG 检索：对建筑空间文化、展览介绍、机构官网、研究文章和城市文化内容进行解析、切片、标签化与向量化处理，结合 Query Rewrite、混合检索、Rerank 与原文引用，提升专业问题的召回率、回答质量及内容可信度；通过向量知识承载建筑设计脉络与文化解释。
  • 文旅规划 Agent 与行程校验评估 Agent：采用“需求追问—画像调用—知识检索—路线规划—约束校验—行程卡片生成”的任务链路，根据用户偏好自主组合用户画像、建筑库、展览库、地图和时间信息，将分散内容生成具有叙事关系的主题路线；天气、交通和餐饮仅作为可执行性约束，并支持旅途中基于闭馆、天气变化与用户反馈进行动态重规划。

模型选型与 0—1 架构验证

  • 基础模型选型：从 0 到 1 建立面向入境游的 Benchmark，选取中英文需求理解、建筑与艺术知识问答、长文本行程规划、多轮追问和结构化输出等典型任务，对候选模型进行横向测试；综合准确性、推理稳定性、多语言能力、上下文长度、响应速度与调用成本，确定主模型、轻量模型及降级模型的分工。
  • 单 Agent 与多 Agent 架构比较：对比单体 Agent、规划—执行双 Agent 及“画像 / 检索 / 规划 / 讲解”多 Agent 架构在任务成功率、链路复杂度、延迟和可维护性上的差异。MVP 阶段优先采用中心规划 Agent + 专用 Skills，降低协作失控与成本；复杂行程再按任务边界拆分专业 Agent。
  • 知识架构选择：验证纯向量 RAG、结构化数据库 + RAG、知识图谱 + RAG 三种方案。最终以结构化库管理城市、展期、开放时间和地理约束，以向量库承载建筑历史、策展文本与文化讲解，并通过关系字段连接人物、地点、时代和主题，在检索质量与建设成本之间取得平衡。
  • 记忆架构验证：区分会话记忆、行程任务状态和长期用户画像，测试摘要压缩、关键事实抽取及按场景召回策略；重点验证兴趣偏好能否跨城市复用、临时约束是否会污染长期画像，以及记忆调用是否真正改变推荐与路线结果。
  • 端到端技术评测：围绕“需求理解—检索召回—路线生成—约束校验—多语言讲解”建立测试集，跟踪任务成功率、引用一致性、幻觉率、路线冲突率、首字延迟和单次任务成本；对失败案例按模型能力、知识缺失、检索策略、Prompt 与技能调用分类，形成“评测—定位—优化—回归”的持续迭代闭环。

PRODUCT DECISION 01

为什么 MVP 不直接使用多 Agent？

早期任务边界尚未稳定，多 Agent 会增加通信成本、延迟与调试复杂度。因此优先采用中心 Planner + 专用 Skills，在复杂任务稳定后再按边界拆分。

PRODUCT DECISION 02

为什么不用纯 Vector RAG？

时间、地点、开放状态和商品库存属于强结构化约束，完全依赖向量召回容易产生冲突。因此采用 Structured DB + Vector RAG，让事实校验与语义解释各自承担合适任务。

PRODUCT DECISION 03

为什么把 Memory 拆成三层？

会话记忆、任务状态与长期画像生命周期不同。分层存储与按场景召回，可以减少错误记忆、临时条件污染和无关上下文带来的决策偏差。
